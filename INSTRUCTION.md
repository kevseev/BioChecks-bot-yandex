# BioChecks Bot (Яндекс Мессенджер + LUNA Platform)

Подробное описание назначения, устройства, настройки и эксплуатации бота.

> Этот файл и `README.md` в репозитории содержат одинаковый текст (копия для удобства: на GitHub по умолчанию открывается `README.md`).

---

## Назначение

Бот для **Яндекс Мессенджера** (Bot API), который по фотографиям и ссылкам на изображения вызывает **LUNA Platform** (анализ через SDK-эндпоинты): сравнение лиц, атрибуты, лайвнес, дипфейк, качество кадра, детекция лиц/тел/толпы, оценка модификации изображения. Ответы приходят в чат текстом и картинками с разметкой (контуры, точки).

---

## Архитектура (модули)

| Компонент | Роль |
|-----------|------|
| `app/runner.py` | Точка входа: цикл **long polling** `getUpdates`, хранение **offset** в файле, вызов обработчика каждого обновления, bootstrap доступа при старте. |
| `app/handlers.py` | Разбор событий: дедупликация `update_id`, сессии и сценарии (**flow**), маршрутизация кнопок меню и вложений, вызов LUNA и отрисовка результатов. |
| `app/yandex_api.py` | HTTP-клиент к `https://botapi.messenger.yandex.net/bot/v1`: `getUpdates`, `sendText`, `sendImage`, `getFile`, конструктор **suggest_buttons** (главное меню). |
| `app/luna.py` | Запросы к LUNA (`sdk_analyze`, matcher), разбор JSON, форматирование ответов на русском. |
| `app/draw.py` | Наложение боксов/точек на изображения для ответов пользователю. |
| `app/url_images.py` | Выделение URL из текста и загрузка изображений по ссылке. |
| `app/state.py` | Состояние сессии в памяти: текущий **режим ожидания** (flow), буфер для сравнения 1:1, флаг авторизации. |
| `app/config.py` | Настройки из переменных окружения и `.env` (Pydantic Settings). |
| `app/access_control.py` | Опциональная **защита паролем**: JSON-хранилище хэшей, bootstrap админов, команды выдачи/отзыва доступа. |
| `Dockerfile`, `docker-compose.yml` | Сборка и запуск в контейнере с томами для данных и файла доступа. |

## Как работает бот (поток данных)

1. **Опрос API.** `runner` периодически вызывает `messages/getUpdates/` с `offset` и `limit`. Интервал между запросами задаётся `YANDEX_POLL_INTERVAL_SEC` (пауза после обработки пачки обновлений).

2. **Смещение (offset).** После успешной обработки пачки `update_id` максимальный из них + 1 записывается в файл (`YANDEX_OFFSET_FILE` / `yandex_offset_file`), чтобы при перезапуске не обрабатывать старые события повторно.

3. **Идемпотентность.** `handlers` отбрасывает повторно пришедшие `update_id` (кольцевой буфер в памяти), чтобы дубли от API не запускали сценарии дважды.

4. **Кому отвечать.** В личном чате используется `login` пользователя; в групповых — `chat_id`. Это определяет параметры `sendText` / `sendImage`.

5. **Опциональная авторизация.** Если включён `BOT_AUTH_ENABLED`, пользователь должен иметь запись в хранилище паролей и один раз ввести пароль **обычным текстом** (без кнопок и вложений). После входа доступны все функции; `!logout` / `/logout` сбрасывает сессию входа. Администраторы (см. ниже) могут выдавать и отзывать доступ текстовыми командами.

6. **Меню и сценарии.** Под ответами бот присылает **suggest_buttons** — кнопки с `server_action`. Нажатие приводит к событию с `name`, например `flow_compare`. Обработчик переводит сессию в соответствующий **flow** и выдаёт инструкцию («пришлите фото…»).

7. **Ввод изображений.** Пользователь может отправить файл из галереи и/или **ссылку** в тексте сообщения. Несколько вложений и URL могут быть объединены в один апдейт; для режимов «одно фото» берётся первое успешно загруженное изображение. Для **1:1** накапливаются до двух снимков (вложения и/или ссылки по очереди).

8. **LUNA.** Для анализа вызывается `sdk_analyze` с набором флагов, специфичным для режима (лица/тела, нужные оценки). Для сравнения лиц дополнительно вызывается **matcher** по двум дескрипторам. Результаты форматируются и отправляются пользователю; часто вместе с JPEG с нарисованными боксами.

## Режимы (кнопки главного меню)

| Кнопка | Действие |
|--------|----------|
| **1 к 1** | Два снимка: дескрипторы лиц → **matcher/raw**, процент схожести; отдельно два кадра с выделенным лицом. |
| **Атрибуты** | Все лица на кадре: для каждого — подпись с атрибутами и фото с контуром **только этого** лица. |
| **Атрибуты тела** | Все тела: аналогично по телам и body-атрибутам. |
| **Лайфнесс** | Одно лицо (лучшее на кадре): оценка liveness. |
| **Дипфейк** | Одно лицо: оценка deepfake. |
| **Качество изображения** | Одно лицо: `estimate_quality` и текстовая сводка. |
| **Детекция лиц** | Каждое лицо — отдельное фото с рамкой. |
| **Тела** | Каждое тело — отдельное фото с рамкой. |
| **Детекция толпы** | `estimate_people_count`: число людей и разметка точек на изображении. |
| **Модификация изображения** | Признаки обработки/модификации кадра (текстовый отчёт). |
| **Сброс** | Сброс состояния сценария и буфера сравнения, возврат к меню. |

Дополнительно: в состоянии **без выбранного режима** если в одном сообщении приходят **два** успешно загруженных изображения, выполняется сравнение **1:1** без предварительного нажатия кнопки. Если пришло одно изображение без режима — бот просит выбрать режим кнопкой.

Текстовые команды: **`/start`**, **`/menu`**, **`меню`**, **`start`** — главное меню; **`отмена`**, **`/cancel`**, **`сброс`** — аналогично кнопке сброса.

## Доступ по паролю (опционально)

Включение: `BOT_AUTH_ENABLED=true`.

**Идентификация пользователя:** нормализованный логин из поля `from.login`, либо `id:<число>`, если логина нет. Без идентификатора вход невозможен (бот сообщит об ошибке).

**Хранилище:** JSON с PBKDF2-хэшами паролей. Путь задаётся `BOT_ACCESS_STORE` или `BOT_ACCESS_STORE_PATH` (в Docker по умолчанию монтирование `./access_auth` → `/data/access_auth`, файл `access_users.json`).

**Первичная настройка (bootstrap):** задайте `BOT_BOOTSTRAP_ADMIN_PASSWORD` и перечислите админов в `BOT_ADMIN_LOGINS` (через запятую) и/или один логин в `BOT_BOOTSTRAP_ADMIN_LOGIN`. При старте для отсутствующих в JSON логинов создаётся запись с этим паролем. Дальше пароли меняются через команды или правку файла.

**Команды для админов** (отправитель должен быть в списке `BOT_ADMIN_LOGINS` и быть в системе как пользователь):

- `!issue <логин>` или `/issue <логин>` — сгенерировать новый пароль для пользователя и показать его **один раз** в чате.
- `!revoke <логин>` или `/revoke <логин>` — удалить пользователя из хранилища.
- `!users` или `/users` — список логинов с доступом.

Любой авторизованный пользователь: `!logout` / `/logout` — выход (нужен повторный ввод пароля).

**Важно для Docker:** если путь `BOT_ACCESS_STORE` указывает на файл в смонтированном каталоге, на хосте должен существовать **файл** `access_users.json`, а не пустая папка с таким именем (иначе Docker создаст каталог и запись сломается). См. комментарии в `.env.example` и `access_control.py`.

## Переменные окружения

| Переменная | Смысл |
|------------|--------|
| `YANDEX_BOT_TOKEN` | OAuth-токен бота Яндекс Мессенджера (**обязательно**). |
| `YANDEX_POLL_INTERVAL_SEC` | Пауза между циклами polling (по умолчанию `2`). |
| `YANDEX_UPDATES_LIMIT` | Лимит обновлений за один запрос `getUpdates`. |
| `YANDEX_OFFSET_FILE` / `yandex_offset_file` | Файл с last offset (в Docker обычно `/data/yandex_updates_offset.txt`). |
| `LUNA_BASE_URL` | Базовый URL API LUNA, например `http://host.docker.internal:5000/6`. |
| `LUNA_HTTP_USER` / `LUNA_HTTP_PASSWORD` | Basic-auth к LUNA (если используется). |
| `LUNA_BEARER_TOKEN` | Bearer-токен к LUNA (альтернатива basic). |
| `BOT_AUTH_ENABLED` | `true` / включить парольный доступ. |
| `BOT_ACCESS_STORE` или `BOT_ACCESS_STORE_PATH` | Путь к JSON с пользователями. |
| `BOT_ADMIN_LOGINS` | Список логинов админов через запятую или `;`. |
| `BOT_BOOTSTRAP_ADMIN_LOGIN` | Дополнительный логин для bootstrap. |
| `BOT_BOOTSTRAP_ADMIN_PASSWORD` | Пароль для создания записей при первом старте. |
| `BOT_PASSWORD_PBKDF2_ITERATIONS` | Итерации PBKDF2 (по умолчанию `200000`). |

Полный список и примеры см. в `.env.example`.

## Запуск в Docker

1. Скопируйте `.env.example` в `.env` и заполните токен и LUNA.
2. При включённой авторизации: `mkdir -p access_auth && cp access_auth/access_users.example.json access_auth/access_users.json`, настройте переменные доступа.
3. Запуск:

```bash
docker compose up -d --build
docker compose logs -f bot
```

Том `bot_state` хранит offset; каталог `./access_auth` пробрасывается в контейнер. Для LUNA на машине-хосте в `.env` часто указывают `LUNA_BASE_URL=http://host.docker.internal:5000/6`; в `docker-compose` добавлен `extra_hosts` для резолва `host.docker.internal` (Linux).

---

## Локальный запуск (без Docker)

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m app.runner
```

Убедитесь, что `LUNA_BASE_URL` доступен с вашей машины и что для бота не включён **webhook** (см. ниже).

## Типовые проблемы

- **`getUpdates` пустой:** у бота в Bot API может быть настроен **webhook**. Для long polling его нужно отключить (`webhook_url: null` у соответствующего метода API), иначе обновления не приходят в polling.
- **Нет связи с LUNA из контейнера:** проверьте URL, firewall, и что используется достижимый с контейнера адрес (`host.docker.internal` на Linux задаётся через `extra_hosts` в compose).
- **Ошибка записи access store «это каталог»:** на хосте удалите ошибочно созданный каталог `access_users.json` и создайте файл по примеру `access_auth/access_users.example.json`.
